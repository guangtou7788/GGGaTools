# GGGaTools 0.3.5 — 悬浮网页与门店查询

本版将“测试”悬窗作为诊断面板。两个发送按钮尝试直接调用 App 内的 `AIMPubMsgService`，不通过聊天输入框。

## 面板功能

**打开网页**在闲鱼上方的悬浮窗中打开 `https://aixiya.cn/`。点「关闭」或窗外空白处收起，点悬浮球继续浏览。网页在 App 运行期间保留当前页和滚动位置，顶部「菜单」可切回插件功能列表。

**查门店**把输入内容作为 `q` 参数发送到 `https://aixiya.cn/api/mendian/`，将 UTF-8 纯文本原样显示。点「复制」将全部结果写入剪贴板。查询面板和普通网页分别保留各自状态。

**桥接方法明细**区分通用分发调用和返回已处理的调用，按次数列出方法标识。使用「记录测试起点」分别测只输入和实际发送，再比较方法名。调用参数和回调内容不进入此探测的统计。

**检查网页容器**会列出当前窗口内可见的 `WKWebView`、`FlutterView` 实例及其位置和尺寸。在首页、聊天列表和聊天详情分别查看，比较容器与聊天区域是否重合。检查只读取视图结构。

**多路径结果**并行显示 Flutter 消息桥接、原生备用接收、本地历史和远端历史的候选入口。每个入口显示「未安装」或自测试起点增加的调用次数。面板还会单独检查发送、接收注册、历史三个 FFI 符号是否能查找到。查找到符号仅说明能定位该候选入口，不能证明当前操作调用了它。新增探测仅统计次数。

在同一测试会话中，分别测试「手动发文字」「手动发图片」「等对方发新文字」「退出并重开会话，向上翻聊天历史」。每项开始前点「记录测试起点」，完成后点「多路径结果」截图。同一次操作即可比较所有新增探针。通用 Flutter 桥接计数可能包含其他界面事件，需要结合各步骤的差异解读。

1. **路径诊断**会区分监听是否安装、入口是否命中、参数在哪一步被筛掉。诊断弹窗只显示计数。复测时先记录基线，再手动发一条文字和一张图片，等测试对象发来新文字后比较计数。
2. **直接发文字**：先在目标测试会话手动发送一条普通文字以捕获发送参数。之后点击此按钮，经二次确认后尝试直接发送固定文字 `【GGGaTools测试】这是一条插件直接发送的测试消息`。不需要打开键盘。
3. **复用图片直发**：先在同一测试会话手动发送一张测试图片。只有捕获的图片参数包含已上传媒体标识且会话一致时，才允许确认后尝试再次发送同一张图片。本版不从相册选择或上传新图片。
4. **最近捕获文字**观察 `AIMManager onMessage:` 中的 `PMessage`，仅在 `isMine == NO` 且有文字时显示最近捕获内容。该路径尚未证实用于当前 Flutter 聊天，结果可能为空或来自其他会话，不能用于自动回复。
5. **清除校准**：清空进程内保存的发送样本和最近文字。切换测试会话前应先清除，再重新校准。校准超过 10 分钟后也会禁止直发。

两种直发都只在你点击确认后调用 SDK。提示“已调用”不代表服务端成功；需核对聊天页和对方设备。不会自动回复或循环发送。

## 已知限制

- 目前只观察 `AIMPubMsgService` 的两个 Objective-C 发送方法。若实际聊天走另一条 FFI 路径，状态会停在“待捕获”，直发按钮不会猜测参数。
- SDK 调用以空监听器和回调执行，不能准确显示服务端发送回执。
- 图片仅复用已发送图片的媒体参数；未实现新图片上传。
- 发送样本仅保存在本次 App 进程内存中。插件日志不写消息正文、接收人或会话 ID。
- 针对闲鱼 7.29.20 的实验代码，真机效果和稳定性尚未验证。

## 拟定验收顺序

在自己的测试会话中，手动发送文字和测试图片后查看“路径诊断”，再让对方发送新文字并比较接收计数。如果监听已安装但命中数未增加，优先检查其他发送或接收路径。如果命中数增加，查看具体筛选项。如果校准成功，再分别尝试直发文字和图片，并在对方设备确认。

从 GitHub Actions 下载 `GGGaTools-0.3.5-iOS-arm64`，解压取得 `GGGaTools-0.3.5.dylib`，再通过 ESign 注入 IPA 测试副本。完整步骤见 [INSTALL.txt](INSTALL.txt)。
